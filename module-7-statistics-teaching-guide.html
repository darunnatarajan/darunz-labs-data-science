7.1 Central tendency

One number that says where the middle of the data sits. There are three ways to pick it (mean, median and mode), and skewness tells you which one to trust.

About 90 minutes

Mean

Add everything up and share it equally. The mean is what each person would get if the total were split fairly.

Add up every value and divide by how many values there are. The mean uses every single data point, which is both its strength and its weakness: one extreme value can drag it a long way.

Say it in class

"5 friends hotel-la saapttu ₹1,000 bill vandhaa, ellarum equal-aa ₹200 podanum. Andha equal share dhaan mean. Aana oruthan mattum ₹600-ku order pannirundhaalum share ₹200 dhaan. Adhu dhaan mean-oda problem."

Formula

x = Σx / nSample mean: add all values, divide by the count n.μ = Σx / NPopulation mean: same idea, when you have every member of the group.

Real-time example

Salaries of a five-person startup team on OMR

Annual salaries in lakhs per annum (LPA): 4, 5, 6, 7, 8.

Mean = (4 + 5 + 6 + 7 + 8) / 5 = 30 / 5 = 6 LPA

Now the founder adds his own salary to the payroll sheet: 60 LPA.

Mean = (4 + 5 + 6 + 7 + 8 + 60) / 6 = 90 / 6 = 15 LPA

A job post that says "average team salary 15 LPA" is technically true and completely misleading. Five of the six people earn 8 LPA or less. One extreme value pulled the mean up two and a half times.

Try it live

Add the founder's salary and watch which marker jumps.

Mean6 LPA Median6 LPA

Python

import pandas as pd

salary = pd.Series([4, 5, 6, 7, 8, 60])
salary.mean()     # 15.0
salary.median()   # 6.5  (next topic explains why)

Where it's used

Filling missing numeric values when a column has no outliers, standardising features (StandardScaler subtracts the mean), and business KPIs like average order value.

Watch out

The mean gets pulled by extreme values. Before reporting the mean of salaries, prices, rents or delivery times, check the median. If the two are far apart, the mean is misleading you.

Median

Line the values up from smallest to biggest. The one standing in the middle is the median.

The middle value once the data is sorted. It only cares about position, not size, so extreme values at either end barely move it.

  • Odd number of values: the single middle value.
  • Even number of values: the average of the two middle values.

Say it in class

"Class-la ellaraiyum height order-la line-aa nikka vechaa, correct-aa naduvula nikkiravar height dhaan median. Line-la kadaisi aal 6 adi-yaa irundhaalum 7 adi-yaa irundhaalum, naduvula irukkuravar adhe aal dhaan."

Formula

Median position = (n + 1) / 2Always sort first. If the position lands between two values (like 3.5), average those two.

Real-time example

Rents in one OMR apartment block

Monthly rents of five flats: ₹15,000, ₹12,000, ₹18,000, ₹85,000 (the penthouse), ₹14,000.

Sorted: 12,000 | 14,000 | 15,000 | 18,000 | 85,000

Position = (5 + 1) / 2 = 3rd value, so median = ₹15,000

The mean is ₹28,800, and not a single tenant pays anywhere near that. This is why rent and salary reports quote the median.

Even count: back to the salaries 4, 5, 6, 7, 8, 60. Position (6 + 1) / 2 = 3.5, so the median is (6 + 7) / 2 = 6.5 LPA, against a mean of 15.

Python

rent = pd.Series([15000, 12000, 18000, 85000, 14000])
rent.median()   # 15000.0  (pandas sorts for you)
rent.mean()     # 28800.0

Where it's used

Filling missing values in skewed columns (income, fare, price), robust summaries in EDA reports, and RobustScaler, which centres data on the median.

Watch out

Forgetting to sort is the most common by-hand mistake. Also, the median ignores size completely: 10, 20, 30 and 19, 20, 900 both have a median of 20.

Mode

The value that turns up most often. The crowd favourite.

The value that appears most often. It's the only measure of centre that works for categories like city, payment method or dish. A dataset can have one mode, two (bimodal), several (multimodal), or none when every value appears once.

Say it in class

"Kalyana veetla 200 per-la 120 per 'chicken biryani' kettaanga-na, biryani dhaan mode. Biryani-kkum curd rice-kkum 'average' kandupidikka mudiyaadhu. Adhanaala text data-ku mode mattum dhaan work aagum."

Formula

Mode = value with the highest frequencyBuild a frequency table and pick the top row.

Real-time example

Shoe sizes sold in one day at a T. Nagar footwear shop

Sizes sold: 7, 8, 8, 9, 8, 10, 7, 8, 9.

SizePairs sold

The mode is size 8, so the owner restocks size 8 first. The mean shoe size is 8.22, which is useless because nobody makes a size 8.22.

Bimodal: hourly orders at a Chennai restaurant peak around 1 PM and again around 8 PM. With two modes, the manager plans two rush shifts, not one "average" rush at 4:30 PM.

Python

sizes = pd.Series([7, 8, 8, 9, 8, 10, 7, 8, 9])
sizes.value_counts()   # 8: 4, 7: 2, 9: 2, 10: 1
sizes.mode()           # a Series containing 8
sizes.mode()[0]        # 8, the form to use when filling missing values

Where it's used

Filling missing categorical values (most common city or payment mode), the majority-class baseline every classifier has to beat, and inventory or menu decisions.

Watch out

pandas .mode() returns a Series because there can be ties, so use .mode()[0] for a single value. On continuous data like exact rupee amounts every value may be unique; group the values into ranges first.

Skewness

Which side has the long tail? The mean always gets dragged toward that tail.

Skewness measures how lopsided a distribution is: which side has the longer tail. The mean always gets pulled toward the tail, so the order of mean, median and mode tells you the direction.

  • Mode
  • Median
  • Mean
TypeTailOrderEveryday examples
Positive (right) skewLong tail to the rightMean > median > modeSalaries, house prices, delivery times, hospital bills
Zero skewBalancedMean ≈ median ≈ modeHeights, machine fill volumes, measurement errors
Negative (left) skewLong tail to the leftMean < median < modeMarks in an easy test, online star ratings, retirement age

Say it in class

"Tail endha pakkam neelamaa pogudho, adhu dhaan skew direction. Mean eppovume andha tail pakkam izhukkapadum. Median konjam dhaan nagarum, mode nagaravae nagaraadhu."

Formula

Pearson's skewness = 3 × (Mean − Median) / SDRough guide: between −0.5 and 0.5 is fairly symmetric, 0.5 to 1 (either sign) is moderate, beyond ±1 is highly skewed. pandas .skew() uses a moment-based formula, so its number differs from this shortcut, but the sign always tells the same direction.

Real-time example

Delivery times on a rainy Chennai evening (right skew)

Ten food orders, in minutes: 22, 25, 26, 28, 30, 30, 32, 35, 60, 95.

Mean = 38.3 | Median = 30 | Mode = 30 | SD = 22.54

Pearson = 3 × (38.3 − 30) / 22.54 ≈ 1.10, highly right-skewed

Advertising "38 minutes on average" misleads both ways. Eight of the ten customers got their food within 35 minutes, while two waited an hour or more. The operations team should chase the tail, those 60 and 95 minute orders, not the average.

Marks in an easy Python quiz (left skew)

Nine learners, out of 100: 30, 45, 80, 85, 88, 90, 90, 92, 95.

Mean = 77.2 < Median = 88 < Mode = 90

Most of the batch is comfortable; two learners need a doubt-clearing session. The class average of 77 hides both facts.

Python

delivery = pd.Series([22, 25, 26, 28, 30, 30, 32, 35, 60, 95])
delivery.skew()   # 2.20, positive so right-skewed

quiz = pd.Series([30, 45, 80, 85, 88, 90, 90, 92, 95])
quiz.skew()       # -1.59, negative so left-skewed

Where it's used

Choosing between mean and median imputation, deciding when to log-transform a feature or target before linear regression (house prices are the classic case), and spotting data that breaks normality assumptions.

Watch out

Skewness from a handful of rows is unstable; one extra value can flip it. Always look at a histogram alongside the number.

Normal distribution

Most values sit near the middle, fewer and fewer as you move away, the same on both sides. Shaped like a temple bell.

A symmetric, bell-shaped distribution described completely by two numbers: the mean μ, where the centre sits, and the standard deviation σ, how wide the bell is. Mean, median and mode are all equal. Values near the centre are common and values far from it are rare, in a very predictable way:

  • About 68% of values fall within 1 standard deviation of the mean.
  • About 95% fall within 2 standard deviations.
  • About 99.7% fall within 3 standard deviations.

This is the empirical rule, or the 68–95–99.7 rule.

Say it in class

"Kovil mani (bell) shape-ai nenachukkonga. Naduvula dhaan kootam adhigam; rendu pakkamum poga poga aalunga kammi, rendu pakkamum same-aa irukkum. Mean, median, mode moonum ore idathula nikkum."

Formula

z = (x − μ) / σThe z-score: how many standard deviations a value sits from the mean.f(x) = 1 / (σ√(2π)) × e−(x − μ)² / 2σ²The density formula behind the curve. Learners don't need to memorise it; they need the z-score and the 68–95–99.7 rule.

Real-time example

A milk packet filling machine

A dairy plant's machine fills 500 ml packets. Over thousands of packets, the fill volume is normally distributed with μ = 502 ml and σ = 3 ml.

RangeVolumeShare of packets
μ ± 1σ499 to 505 mlabout 68%
μ ± 2σ496 to 508 mlabout 95%
μ ± 3σ493 to 511 mlabout 99.7%

A quality inspector picks up a 490 ml packet.

z = (490 − 502) / 3 = −4

A value four standard deviations below the mean happens about 3 times in 100,000 packets by chance. So the line is stopped and the machine is checked. That's statistical quality control in one line.

Comparing marks across subjects

Priya scores 78 in Maths (class mean 65, SD 5) and 85 in English (class mean 80, SD 10).

Maths: z = (78 − 65) / 5 = 2.6
English: z = (85 − 80) / 10 = 0.5

Her English mark is higher, but her Maths performance is far more exceptional compared with her class. z-scores let you compare marks on different scales fairly.

Python

from scipy import stats

# Share of packets between 496 and 508 ml
stats.norm.cdf(508, loc=502, scale=3) - stats.norm.cdf(496, loc=502, scale=3)   # 0.9545

z = (490 - 502) / 3   # -4.0
stats.norm.cdf(z)     # 0.00003, about 3 packets in 100,000

One-line bonus: the bell shows up everywhere because of the Central Limit Theorem. Averages of many random samples tend to be normal even when the raw data isn't. It becomes important later for confidence intervals and hypothesis tests.

Where it's used

StandardScaler (it turns every feature into z-scores), the |z| > 3 outlier rule, the assumptions behind linear regression residuals and Gaussian Naive Bayes, and confidence intervals.

Watch out

Don't assume every column is normal. Salaries, rents and delivery times are skewed, and the 68–95–99.7 rule gives wrong answers on them. Check a histogram or a Q-Q plot first.

Checkpoint 7.1

Ask these before starting 7.2. Tap a question to reveal its answer.

Q1. Find the mean, median and mode of 3, 7, 7, 2, 9.

Sorted: 2, 3, 7, 7, 9. Mean = 28 / 5 = 5.6, median = 7, mode = 7. The mean sitting below the median hints at a slight left skew.

Q2. A Chennai IT company's salaries show a mean of ₹9 LPA and a median of ₹6 LPA. Which way is the data skewed, and which figure should HR quote to freshers?

Right (positive) skew: a few high salaries pull the mean above the median. HR should quote the median, because it's what a typical employee earns.

Q3. Which measure would you use to fill missing values in a "Payment method" column?

The mode. The column is categorical, so a mean or median doesn't exist.

Q4. Exam marks are normally distributed with mean 60 and SD 8. Roughly what share of students scored between 44 and 76?

44 is μ − 2σ and 76 is μ + 2σ, so about 95%.

7.2 Probability basics

Almost every model learners will build outputs a probability: will this customer leave, is this email spam, is this transaction fraud. This unit gives them the language for "how likely", plus the odds ratio that logistic regression speaks in.

About 70 minutes

What does probability mean?

A number from 0 (never happens) to 1 (always happens) that says how likely something is.

Probability is a number from 0 to 1 that measures how likely an event is. 0 means impossible, 1 means certain, and 0.5 is a coin flip. You can write the same probability as a fraction (1/2), a decimal (0.5) or a percentage (50%).

When all outcomes are equally likely, you can count: favourable outcomes divided by total outcomes. The chance that the event doesn't happen is 1 minus its probability.

Say it in class

"Weather app 'naalaikku 70% mazhai' nu sonnaa, idhe maadhiri climate irundha 100 naal-la kitta thatta 70 naal mazhai peidhirukku nu artham. 100% guarantee illa. Aana kudai eduthuttu povadhu nalladhu."

Formula

P(E) = favourable outcomes / total outcomes
0 ≤ P(E) ≤ 1
P(not E) = 1 − P(E)

Real-time example

A sweet box, a mail server and a bank

Sweet box: 12 sweets inside, 4 Mysore pak and 8 laddus. Pick one without looking.

P(Mysore pak) = 4 / 12 ≈ 0.33
P(not Mysore pak) = 1 − 0.33 = 0.67

Mail server: a company received 1,000 emails yesterday and 150 were spam.

P(spam) = 150 / 1,000 = 0.15

Bank: a fraud model scores a card transaction at P(fraud) = 0.92. The bank doesn't wait for certainty. Anything above its chosen threshold, say 0.80, is held and an OTP goes to the customer.

ProbabilityPercentReads as

Python

import numpy as np

rolls = np.random.randint(1, 7, size=10_000)   # 10,000 dice rolls
(rolls == 6).mean()                             # about 0.167, close to 1/6

Where it's used

Every classifier's predict_proba output, choosing decision thresholds, A/B test results and risk scores.

Watch out

A probability describes the long run, not a promise. A 0.92 fraud score can still be a genuine customer, which is why banks confirm with an OTP instead of blocking the card outright. And the probabilities of all possible outcomes must add up to 1.

Types of probability

Chance of one thing (marginal), of two things together (joint), or of one thing when you already know another (conditional).

Teach this in two groups. The first is about where the number comes from. The second is about how many events you're looking at, and that second group is the one ML uses every day.

By where the number comes from

TypeHow it's worked outExample
Classical (theoretical)By reasoning, when every outcome is equally likelyP(King from a deck of cards) = 4 / 52 ≈ 0.077
Empirical (experimental)By counting what actually happened in data240 of 2,000 broadband customers cancelled last quarter, so P(cancel) = 0.12
SubjectiveFrom judgement or experienceA sales head feels 80% sure the Coimbatore client signs this month

Axiomatic probability is the rulebook under all three: a probability is never negative, all outcomes add up to 1, and for events that can't happen together you add their probabilities. Data scientists mostly work with empirical probability, because the dataset is the experiment.

By how many events are involved

Say it in class

"Motha class-la evlo per late-aa varaanga? Adhu marginal. Bus-la vandhu AND late-aa varavanga evlo per? Adhu joint. Bus-la varavangala mattum eduthaa, adhula evlo per late? Adhu conditional."

Real-time example

Customer churn at a Chennai telecom company

200 customers, split by plan and by whether they left in the last quarter.

Prepaid customers churn at four times the rate of postpaid customers (0.40 against 0.10), so the retention budget should go to prepaid first.

If plan type and churn were unrelated, P(Prepaid and Churn) would be 0.5 × 0.25 = 0.125. It's actually 0.20, so the two are linked.

Formula

Marginal: P(A) = count of A / total
Joint: P(A ∩ B) = count of A and B together / total
Conditional: P(A | B) = P(A ∩ B) / P(B)
Independent events only: P(A ∩ B) = P(A) × P(B)

Python

df = pd.DataFrame({
    "plan":  ["Prepaid"] * 100 + ["Postpaid"] * 100,
    "churn": ["Yes"] * 40 + ["No"] * 60 + ["Yes"] * 10 + ["No"] * 90,
})

pd.crosstab(df["plan"], df["churn"], margins=True)       # counts with totals
pd.crosstab(df["plan"], df["churn"], normalize="all")    # joint probabilities
pd.crosstab(df["plan"], df["churn"], normalize="index")  # P(churn | plan): Prepaid, Yes = 0.40

Where it's used

Naive Bayes is built entirely on conditional probability. Churn and conversion rates by segment drive most business dashboards. Bayes' theorem, the natural next step, flips P(A | B) into P(B | A).

Watch out

P(A | B) is not P(B | A). P(Churn | Prepaid) = 0.40, but P(Prepaid | Churn) = 40 / 50 = 0.80. "40% of prepaid users churn" and "80% of churners are prepaid" are different statements, and mixing them up leads to wrong business calls.

Odds ratio

Odds compare "it happens" with "it doesn't happen". The odds ratio compares those odds between two groups.

Odds compare the chance an event happens with the chance it doesn't. A probability of 0.8 gives odds of 0.8 / 0.2 = 4, read as "4 to 1".

The odds ratio (OR) compares the odds in two groups, like the odds of churning for prepaid against postpaid customers.

  • OR = 1: the group makes no difference.
  • OR > 1: the first group has higher odds.
  • OR < 1: the first group has lower odds.

Say it in class

"Home ground-la 5 match-la 4 jeichu 1 thothaa, jeikkira odds 4 : 1. Probability 4/5 = 0.8. Rendu group-oda odds-ai divide panni compare panradhu dhaan odds ratio."

Formula

Odds = p / (1 − p)
p = odds / (1 + odds)
OR = odds in group 1 / odds in group 2
For a 2×2 table with cells a, b (row 1) and c, d (row 2): OR = (a × d) / (b × c)

Real-time example

The same telecom churn table

Odds of churn, prepaid = 40 / 60 = 0.667
Odds of churn, postpaid = 10 / 90 = 0.111
OR = 0.667 / 0.111 = 6.0

Shortcut: (40 × 90) / (60 × 10) = 3,600 / 600 = 6

Say it as: prepaid customers have 6 times the odds of churning compared with postpaid customers.

The ratio of probabilities (relative risk) is 0.40 / 0.10 = 4, so prepaid customers are 4 times as likely to churn. Both statements are correct; they measure different things. Train learners to say "times the odds" for the odds ratio and "times as likely" for relative risk.

Reading logistic regression (the exponent of a coefficient is the odds ratio for a one-unit increase in that feature), medical and insurance studies such as smokers against non-smokers, credit risk, and marketing campaign results.

Watch out

"6 times the odds" is not "6 times as likely". The two only come close when the event is rare, roughly under 10%. And if any cell in the table is 0 the formula breaks; the usual fix is to add 0.5 to every cell.

Checkpoint 7.2

Ask these before starting 7.3.

Q1. A laptop passes quality check with probability 0.8. What are the odds of passing?

0.8 / 0.2 = 4, or 4 to 1.

Q2. "Over the last six months, 12% of orders were cancelled." Which type of probability is this?

Empirical. It's counted from observed data.

Q3. From the churn table, what is P(Prepaid | Churn), and why isn't it 0.40?

40 / 50 = 0.80. It asks "of the customers who churned, how many were prepaid?", while 0.40 answers "of the prepaid customers, how many churned?"

Q4. A WhatsApp coupon campaign: 120 of 500 customers who got a coupon made a purchase, and 60 of 500 without a coupon did. What's the odds ratio?

Coupon: 120 bought, 380 didn't. No coupon: 60 bought, 440 didn't. OR = (120 × 440) / (380 × 60) ≈ 2.32. Customers with a coupon had about 2.3 times the odds of buying.

7.3 Standard deviation

The mean says where the centre is. It says nothing about how spread out the data is, and two datasets with the same mean can behave completely differently.

About 50 minutes

Data deviation and distribution

How far each value sits from the average. Standard deviation is the typical distance.

A deviation is how far one value sits from the mean: x − x. Values above the mean have positive deviations and values below have negative ones.

Deviations always add up to exactly zero, so averaging them tells you nothing. Standard deviation fixes that: square the deviations, average them, then take the square root. The result is the typical distance of a data point from the mean.

  • Small SD: values packed tightly around the mean. Consistent and predictable.
  • Large SD: values spread widely. Hard to predict.

In a normal distribution the SD sets the width of the bell, which is why 68% of values land within one SD of the mean.

Say it in class

"Rendu batsman-um 5 match-la average 50 dhaan. A daily 48 to 52 adippaaru; B oru naal duck, adutha naal century. Selector-aa irundhaa World Cup-ku yaarai eduppeenga? Andha consistency-ai number-aa sollradhu dhaan standard deviation."

Formula

Deviation = x − x
Σ(x − x) = 0, always
Sample SD: s = √[ Σ(x − x)² / (n − 1) ]
Population SD: σ = √[ Σ(x − μ)² / N ]

Real-time example

Two batsmen with the same average

Runs in their last five matches.

Both average 50 and both sets of deviations add up to zero. The difference is spread: A's SD is 1.58 runs and B's is 45.28. For a tense chase the selector wants A. For a gamble on a big score, maybe B. Either way the choice now rests on a number, not a feeling.

Two mutual funds with the same return

Funds X and Y both averaged a 12% return a year over ten years. Fund X's yearly returns have an SD of 2%; Fund Y's have an SD of 15%. In finance the SD of returns is called volatility. In a bad year Fund Y could easily post a loss (12% − 15% = −3%), while Fund X barely moves. Same mean, very different risk.

Python

a = pd.Series([48, 50, 52, 49, 51])
b = pd.Series([0, 100, 10, 90, 50])

(a - a.mean()).sum()   # 0.0, deviations always cancel out
a.std()                # 1.58
b.std()                # 45.28

Where it's used

StandardScaler divides by the SD, z-score outlier detection, volatility and risk metrics, control charts in manufacturing, and error bars in reports.

Watch out

SD is in the same units as the data (runs, rupees, minutes), which makes it easy to explain. But because it squares deviations, a single outlier inflates it heavily. On skewed data, report the IQR alongside it.

Variance

Square each distance from the mean and average the squares. That's variance. Take its square root and you're back to standard deviation.

Variance is the average of the squared deviations, the step just before taking the square root. So SD = √variance, and variance = SD².

Squaring does two jobs: it removes the minus signs, and it punishes large deviations far more than small ones. The catch is the unit. The variance of runs is measured in runs², which nobody can picture. That's why we report the SD and keep variance for the maths underneath.

Sample or population? Divide by N when you have the whole population. Divide by n − 1 when you have a sample, which is almost always the case in data science. The smaller divisor corrects a sample's habit of underestimating the true spread; this is called Bessel's correction.

Say it in class

"Deviation-ai square panni average pannaa variance. Aana commentary-la 'avar consistency 2.5 runs-square' nu yaarum solla maattaanga. Adhanaala square root eduthu thirumba runs unit-ku kondu varom. Adhu dhaan SD."

Formula

Sample variance: s² = Σ(x − x)² / (n − 1)
Population variance: σ² = Σ(x − μ)² / N
Standard deviation = √variance

Real-time example

Working it out for both batsmen

  2. Subtract the mean from each value to get the deviations.
  3. Square each deviation.
  4. Add up the squares.
  5. Divide by n − 1 for a sample (or N for a population). That's the variance.
  6. Take the square root. That's the standard deviation.

Batsman A: variance = 10 / 4 = 2.5 runs², SD = √2.5 = 1.58 runs
Batsman B: variance = 8,200 / 4 = 2,050 runs², SD = √2,050 = 45.28 runs

If these five matches were the entire population, A's variance would be 10 / 5 = 2 and the SD 1.41.

Bonus: the coefficient of variation, SD / mean × 100, compares spread across different scales. A = 3.2%, B = 90.6%.

Python

Where it's used

PCA ranks directions by how much variance they capture, VarianceThreshold drops near-constant features, and the "variance" in the bias–variance tradeoff (next unit) borrows the same idea of spread.

Watch out

The pandas and NumPy defaults trip up almost everyone. On the same data, Series.std() gives 1.58 and np.std() gives 1.41. Pass ddof=1 to NumPy when you're working with a sample.

Checkpoint 7.3

Ask these before starting 7.4.

Q1. Find the population SD of 2, 4, 4, 4, 5, 5, 7, 9.

Mean = 40 / 8 = 5. Squared deviations: 9, 1, 1, 1, 0, 0, 4, 16, which add to 32. Variance = 32 / 8 = 4, so SD = 2.

Q2. Why do we square the deviations instead of just averaging them?

Deviations always sum to zero, so their plain average is always zero. Squaring removes the signs and gives bigger gaps more weight.

Q3. Two delivery partners both average 30 minutes. Partner P has an SD of 3 minutes and partner Q has 12. Who should get the guaranteed 30-minute premium orders?

Partner P. Same mean, but the smaller SD means far more predictable delivery times.

Q4. df["salary"].std() and np.std(df["salary"].values) give different answers. Why?

pandas divides by n − 1 (sample) and NumPy divides by N (population) by default. Use ddof=1 in NumPy to match.

7.4 Bias–variance tradeoff

Every model makes two kinds of mistake. Bias is the error of being too simple to see the pattern. Variance is the error of being so flexible that the model learns the noise. Push one down and the other tends to go up, so the job is finding the balance.

About 60 minutes

Too simple and the model misses the pattern. Too complex and it memorises the noise. Aim for the middle.

Bridge from 7.3: "variance" here is about the model. It means how much the model's predictions would change if you trained it on a different sample of the same data. It's the same idea of spread, applied to predictions instead of raw values.

Say it in class

"Exam-ku moonu vidha students. Onnu: book-ai thirandhe paakkaama ellaa question-ukkum ore answer ezhudhuravan. Adhu underfit. Rendu: last year question paper-ai vari vari-yaa mug-up pannavan. Same question vandhaa 100, konjam maathi kettaa zero. Adhu overfit. Moonu: concept purinju padichavan, endha question vandhaalum answer pannuvaan. Adhu good fit."

Formula

Expected test error = Bias² + Variance + Irreducible noiseNo model can remove the noise. Bias and variance can only be traded against each other.

SituationTraining errorTest errorGapDiagnosis
UnderfittingHighHighSmallHigh bias
Good fitLowLowSmallBalanced
OverfittingVery lowHighLargeHigh variance

Underfitting

The model is too simple. It does badly everywhere, even on data it has already seen.

The model is too simple for the pattern in the data: high bias, low variance. It performs badly on the training data and just as badly on new data, because it never learned the relationship in the first place.

Signs: a low training score, and a test score that's about as low.

Say it in class

"Ellaa flat-kkum 'sq.ft × ₹5,000' nu ore rate pottaa, Adyar flat-um Tambaram flat-um same price aayidum. Simple-aa irukku, aana ellaa idathilum thappu."

Real-time example

Predicting Chennai flat prices from square feet alone

A straight-line model uses a single feature: area. It predicts roughly the same price for a 1,000 sq ft flat in Adyar and one in Tambaram, so it's wrong almost everywhere.

More data rarely rescues an underfit model. A straight line fitted to a million curved points is still a straight line. Fix the model or the features first.

Overfitting

The model memorised the training data. Full marks in practice, poor marks in the real exam.

The model is too complex for the amount of data: low bias, high variance. It memorises the training rows, noise and one-off accidents included, so it scores brilliantly on training data and disappoints on anything new.

Signs: a very high training score and a clearly lower test score, with a big gap between them.

Say it in class

Ask these before starting 7.5.

Q1. Training accuracy is 98% and test accuracy is 71%. What's happening, and what are two fixes?

Overfitting (high variance). Limit model complexity such as max_depth, add regularisation, get more data, or tune with cross-validation.

Q2. Training accuracy is 62% and test accuracy is 60%, on a task where people score 95%. Diagnosis?

Underfitting (high bias). Add better features, use a more flexible model or reduce regularisation.

Q3. Will collecting ten times more data fix an underfitting model?

Usually not. More data mainly helps overfitting; an underfit model needs more capacity or better features.

7.5 Distance metrics

"How similar are these two?" is a distance question. KNN, K-means and recommendation systems all start by measuring how far apart two rows of data are. Two rulers do most of that work.

About 45 minutes

Euclidean distance

The straight-line distance between two points, as the crow flies.

It comes straight from Pythagoras: square the difference along each axis, add them, take the square root. It works the same way with 2 features or 200.

Say it in class

"Drone-la biriyani anuppina, building mela straight-aa parandhu varum. Road, signal, U-turn edhuvum kidaiyaadhu. Adhu dhaan Euclidean distance: kaakka parakkura distance."

Formula

Two features: d = √[ (x₂ − x₁)² + (y₂ − y₁)² ]
Any number of features: d = √[ Σ (pᵢ − qᵢ)² ]

Real-time example

Drone delivery from a restaurant to a home

On the city grid the restaurant is at (1, 2) and the home is at (4, 6), in kilometres.

Across: 4 − 1 = 3   Up: 6 − 2 = 4
d = √(3² + 4²) = √(9 + 16) = √25 = 5 km

The 3–4–5 triangle makes this the easiest example to do on the board.

Which student is most like Student S?

Marks in Maths, Science and English.

Q80704515.0

S to P: √(5² + 5² + 5²) = √75 ≈ 8.66
S to Q: √(0² + 0² + 15²) = √225 = 15

P is closer, so a KNN model would group S with P. Hold on to this table: Manhattan distance gives a surprising answer for it in the next topic.

Where it's used

The default distance in KNN and K-means, finding similar customers or products, and clustering locations on a map.

Watch out

Always scale your features first. Three customers: A is 25 years old earning ₹40,000; B is 45 earning ₹40,500; C is 26 earning ₹45,000. Who is closest to A?

Manhattan distance

The distance you travel when you can only move along the streets: across, then up. No shortcuts through buildings.

Add up the plain differences along each axis, with no squaring. It's also called city-block or taxicab distance, after the street grid of Manhattan in New York.

Say it in class

"Auto-la vandhaa T. Nagar street-la right, left nu turn adichu dhaan varanum. Building-ukku naduvula poga mudiyaadhu. Street-oda poradhu dhaan Manhattan distance."

Formula

Two features: d = |x₂ − x₁| + |y₂ − y₁|
Any number of features: d = Σ |pᵢ − qᵢ|

Real-time example

The same trip, by auto

Restaurant at (1, 2), home at (4, 6). The auto goes 3 blocks across and 4 blocks up.

d = |4 − 1| + |6 − 2| = 3 + 4 = 7 km

Manhattan is never shorter than Euclidean. For a delivery app estimating road distance, 7 km is the honest number.

The student tie

Back to Student S. With Manhattan distance:

S to P: 5 + 5 + 5 = 15
S to Q: 0 + 0 + 15 = 15

A tie. Manhattan treats "a little different in every subject" and "very different in one subject" the same. Euclidean squares the gaps, so one big gap counts more; that's why it picked P. Neither is wrong. Ask: does one big difference matter more than several small ones?

A warehouse picking robot

In an Amazon-style warehouse the robot can only drive along the aisles. To reach a shelf 6 aisles across and 8 slots down, it travels 6 + 8 = 14 units, not the straight-line 10.

Where it's used

Route estimates on road grids, KNN on high-dimensional data (it copes better than Euclidean when there are many features), and L1 regularisation, which is Manhattan distance applied to model weights.

Watch out

Scaling matters here too, for exactly the same reason. And when two points differ in only one feature, both distances give the same answer, so don't be surprised when they match.

Checkpoint 7.5

Ask these before starting 7.6.

Q1. Find the Euclidean and Manhattan distance between (1, 1) and (7, 9).

Differences are 6 and 8. Euclidean = √(36 + 64) = √100 = 10. Manhattan = 6 + 8 = 14.

Q2. A cab app wants to estimate the fare from road distance. Which metric fits better?

Manhattan. Cabs follow streets, so the straight-line distance underestimates the trip.

Q3. Why must you scale age and income before running KNN?

Income is in thousands and age is in tens, so income decides the distance almost on its own. Unscaled, a 20-year age gap looked 10 times smaller than a ₹5,000 income gap.

Q4. When do Euclidean and Manhattan give the same answer?

When the two points differ along only one feature, for example (3, 5) and (9, 5): both give 6.

7.6 Outlier analysis

One strange value can wreck a mean, blow up a standard deviation and mislead a model. This unit shows how to spot it with a simple rule, how to draw it, and what to do about it.

What is an outlier?

A value that sits far away from the rest of the data, like one very tall person in a class photo.

Outliers come in two kinds, and telling them apart is the most important skill in this unit:

Where it's used

Interquartile range (IQR)

Cut the sorted data into four equal parts. The IQR is the width of the middle two parts, where the central 50% of the data lives.

Quartiles split sorted data into quarters. Q1 has 25% of values below it, Q2 is the median, and Q3 has 75% below it. Because the IQR ignores the top and bottom quarters, extreme values can't stretch it. That makes it the right ruler for measuring what counts as "too far".

Say it in class

"Marks-ai sort pannunga. Keezha irukkura 25% students-aiyum, mela irukkura 25% students-aiyum konjam oram vachidunga. Naduvula irukkura 50% students-oda range dhaan IQR."

Formula

IQR = Q3 − Q1
Lower fence = Q1 − 1.5 × IQR
Upper fence = Q3 + 1.5 × IQRAnything below the lower fence or above the upper fence is flagged as an outlier.

Real-time example

Finding the outliers in the order data

  1. Sort: 42, 45, 48, 50, 52, 53, 55, 57, 58, 60, 62, 65, 120.
  2. Quartiles: Q1 = 50, median = 55, Q3 = 60.
  3. IQR = 60 − 50 = 10.
  4. Lower fence = 50 − 1.5 × 10 = 35. Upper fence = 60 + 1.5 × 10 = 75.
  5. Check: nothing is below 35; 120 is above 75. So 120 is the only outlier.

Python

orders = pd.Series([55, 48, 60, 120, 52, 45, 58, 62, 50, 42, 65, 53, 57])

q1, q3 = orders.quantile([0.25, 0.75])     # 50.0, 60.0
iqr = q3 - q1                               # 10.0
lower = q1 - 1.5 * iqr                      # 35.0
upper = q3 + 1.5 * iqr                      # 75.0
orders[(orders < lower) | (orders > upper)]  # 120

Where it's used

The standard outlier rule in data cleaning, the basis of every box plot, and a spread measure you can trust on skewed data like salaries and prices.

Watch out

Hand calculations can give slightly different quartiles. Using the "median of each half" method, learners get Q1 = 49 and Q3 = 61, so IQR = 12 and fences of 31 and 79. pandas interpolates and gives 50 and 60. Both are accepted methods; 120 is an outlier either way. Just use one method consistently.

Upper whisker

The upper whisker stops at the largest real value that is still inside the upper fence. It is a data point, not the fence.

Say it in class

"Fence enbadhu oru rule, oru kodu mattum. Whisker enbadhu real-aa data-la irukkura oru value. Fence-ku ulla irukkura biggest value dhaan upper whisker. Interview-la idhu dhaan trap question."

Formula

Upper whisker = the largest value that is ≤ Q3 + 1.5 × IQR
Lower whisker = the smallest value that is ≥ Q1 − 1.5 × IQRIf there are no outliers on a side, the whisker simply ends at the maximum (or minimum).

Real-time example

Where does the upper whisker end?

Upper fence = 75
Values at or below 75: 42, 45, 48, 50, 52, 53, 55, 57, 58, 60, 62, 65
Largest of these = 65, so the upper whisker ends at 65

The common wrong answers are 75 (that's the fence, not a data point) and 120 (that's the outlier).

Python

upper_whisker = orders[orders <= upper].max()   # 65
lower_whisker = orders[orders >= lower].min()   # 42

Where it's used

Reading box plots correctly in reports and dashboards, capping outliers (some teams cap at the whisker instead of the fence), and interview questions on EDA.

Watch out

Different tools can draw whiskers differently: some go to the minimum and maximum, some to fixed percentiles. matplotlib and seaborn use the 1.5 × IQR rule by default (whis=1.5). Check the setting before explaining a chart someone else made.

Overfitting (high variance): with only 15 rows, the tree memorised each flat, including the typo. Fix the data first, then limit max_depth, collect more flats, and judge the model with cross-validation instead of the training score.
